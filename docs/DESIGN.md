# Airliner Sim — 技術設計ドキュメント

iPhone Safari で動作する、**グラフィック品質を最優先**した 3D 旅客機フライトシミュレーター。
最終目標: 離陸→巡航→着陸までを体験できる、実機的な重みのある旅客機シミュレーション。

---

## 1. 技術選定とその理由

| 項目 | 採用 | バージョン | 理由 |
|---|---|---|---|
| 言語 | **TypeScript** | 5.6.3 | 型安全な大規模開発。Vite でそのままビルド |
| 3D 描画 | **Three.js** | **0.170.0 固定** | WebGL ベース、iPhone Safari 実績、glTF/PBR エコシステム |
| ビルド | **Vite** | **5.4.11 固定** | 高速 HMR、静的ビルド（`base:'./'` で任意ホスティング可） |
| 型定義 | @types/three | 0.170.0 固定 | three と型を一致 |
| モデル形式 | **glTF/GLB 準拠のパイプライン** | — | 業界標準。外部アセット未取得のため **Phase 1 は手続き生成**（後述 3.1）。`GLTFLoader` で GLB に差し替え可能な構造 |
| テクスチャ | CanvasTexture（手続き生成）+ **KTX2 は将来オプション** | — | 外部アセットなしで完結。KTX2/Basis はモデル大規模化時に追加（バンドル肥大回避のため Phase 1 では未導入） |
| 物理 | 描画から分離した独立モジュール（Phase 3） | — | Phase 1 は描画基盤のみ。物理は `src/sim/` に配置し描画非依存で実装予定 |

## 3. グラフィック実装方針

### 3.1 機体モデル（滑らかな曲面）
- **胴体**: `LatheGeometry`（プロファイル曲線を回転）＋尾部アップスイープを頂点変形で付与。箱/円柱の集合に**しない**
- **主翼/尾翼**: 翼型断面（NACA 系の厚み分布＋キャンバー）を翼幅方向に **ロフト（放物線状態のグリッド接続）**。後退角・上反角・テーパー・翼端レット
- **エンジン**: ナセル（ラシ＋インテークリップ＋排気テーパー）＋ファン面テクスチャ＋パイロン
- **塗装**: 胴体に窓列/ドア/ラインストライプの CanvasTexture、PBR 塗装（metalness 0.4 / roughness 0.3 / clearcoat）
- **着陸装置**: 前脚/主脚（ストラット＋車輪、機種別ブギー）。`setGearPosition(0..1)` で展開アニメ
- **塗装バリエーション**: B737 / B777 / A320 で全寸法・エンジン径・尾翼高・リバリー色を分離（`config/aircraft.ts` 一元管理）
- Phase 2 で GLB モデルに差し替え可能な `buildAircraft()` インターフェイス

### 3.2 空港（近景高精細）
- 滑走路 4,000m×60m: アスファルトノイズ＋中央線・停止線・番号「34/16」・タッチダウンゾーンの手続きテクスチャ
- 並行誘導路・連絡路・エプロン（コンクリート色分け）、発光エッジライト
- ターミナル（ガラス帯テクスチャ）・管制塔（傾斜円柱＋グラスキャブ）・格納庫（半円筒）
- 駐機中の旅客機（同一生成器の低ディテールコピー）・エプロン車両
- 遠景: fBm 山岳地形（低解像度メッシュ＋フォグで霞）、市街地（InstancedMesh 300 棟＋窓テクスチャ）、森林（Instanced 1,000 本）

### 3.3 空・大気・光
- **大気散乱風シェーダ**: 天頂→地平のグラデーション、太陽ディスク＋グロー、太陽方位の暖色ハズレ、高度で変化する色味（`uSunElevation` パラメータで朝/昼/夕方へ拡張可能）
- **IBL**: プロシージャル空から `PMREMGenerator` で環境マップを生成し `scene.environment` に設定 → 塗装/ガラス/金属の反射が PBR として成立
- **影**: 平行光＋PCFSoft。影カメラは空港周辺に限定（±2.5km）。接地時の影＝機体の castShadow
- **フォグ/霞**: 地平線色に一致した線形フォグ＋遠景の明度上昇（エアリアルパースペクティブ）
- **雲**: 2〜3 層のソフトスプライト（低層積雲＋高層巻雲）＋シェーダによる立体感（下方向の陰影付きテクスチャ）
- **トーンマッピング**: ACESFilmic + sRGB 出力。重いポストプロセスは使用しない

### 3.4 品質と LOD
- 市街地・森林は InstancedMesh（各 1〜2 ドローコール）
- 遠景地形はフォグでフェード（遠方の詳細ゼロ）
- 描画距離・影・ピクセル比は `core/quality.ts` の画質プリセット（高/中/低）で切替

### 3.5 地面のチカチカ（zファイティング / シマー）対策

**症状**: 離着陸・タキシー中に滑走路や地形が明滅する。原因は 4 系統あり、それぞれ別々に潰した。

1. **深度バッファ精度不足**（遠方の舗装レイヤー間）
   Δz ≈ z²·(1/near − 1/far)/2²⁴ 。旧 near=0.6 / far=60000 では 6km 先で ≈3.6m ≫ レイヤー間隔 1cm。
   → カメラモード別の near（0.25〜2.5m）と far=46000（`render/cameras.ts` の `NEAR`/`updateDepthRange()`）。
2. **数 cm の実ギャップ + polygonOffset 併用の交叉タイ**
   実ギャップ g と units バイアス Δu·r(z)（r は深度 1 LSB ∝ z²）は g = Δu·r(z*) で正味 0 になり、
   z* の距離帯で全面が二状態明滅（実測 19.6%、地上 12m の視点）。near/far を揺らす検査では
   両面が等倍されるため検出できず、カメラ微小回転検査（flicker-test の [B]）でのみ現れる。
   → **舗装の真下に別の大きな平面を置かない**（路盤ボックス廃止、下地は地形）。
     舗装同士も重ねず突合せ（接続誘導路を滑走路端〜誘導路端の 197m に短縮）。
3. **海面 vs 地形 / 地形の自己重なり（遠景）**
   海岸線では 0〜3m ギャップが約 10km 以遠で量子化に埋没。
   → 海面は背景レイヤー化（depthTest/Write 無効・renderOrder −9）、海面下の地形はシェーダで discard、
     地形には 14〜23km の追加霧フェード（`terrain.ts` の onBeforeCompile）。
4. **エッジのシマー（_aliasing_）** → MSAA（`antialias: true`）+ テクスチャ anisotropy 8。
   2×2 要因実験（near/far×MSAA、結論記載後に一時スクリプトは削除済み）で MSAA は diff>64 を改善することを確認済み。

**計測**: `scripts/flicker-test.mjs`（960×540・8フレーム）。
[A] near/far 微小変更＝画像を動かさず深度比較のみ変化（床 0% の zファイティング検出器）、
[B] 純回転サブピクセルジッタ＝エッジのシマー。legacy（旧 near/far・MSAA 無）との A/B。
最終結果: [A] 0.02〜0.45%（旧 0.14〜5.17%）、[B] diff>24 は 2km ビューで 51.3% → 0.99%。

**既知の制約**: 11〜26km の山並みは地形自身の自己重なりでタイが残る（flicker-test coast [A] ≈0.45%、
シーン霧 16〜63% と追加フェードで減衰済み。実プレイのカメラ距離 ≦10km では発生しない）。

### 3.6 地形 v2 — 立体感・距離感の改修（クリップマップ方式）

**原因分析（改修前コードの検証結果）**:
1. 52km を 192 分割 = **270m/quad の単一メッシュ**。低高度 300m の視界（〜5km）に
   10〜20 quad しか無く、それより小さい起伏が原理的に存在しない → 「平面に色を塗った」見た目。
2. 頂点カラー/頂点法線がメッシュ解像度に紐づく → 斜面陰影が超低周波で立体感なし。
3. `renderer.shadowMap` が一度も有効化されておらず、地形の castShadow も未設定 →
   太陽光 DirectionalLight の影手がかりがゼロ（光っているが平坦）。
4. 山は「fBm を貼った緩やかなうねり」で、稜線・谷のダイナミクス不足。
5. 海岸/遠景の明滅対策（§3.5）で海面を背景レイヤー化していたため、海陸の境界が平坦帯に見えていた。

**方式**:
- **GPU 変位クリップマップ**（3 パッチ: 48km/250m・8km/50m・2km/12.5m、画素密度はほぼ一定）。
  頂点シェーダで手続き高度場を変位 → 近景だけメッシュを密にできる。静的 topology なので
  ストリーミング不要。パッチ境界は**親レベルの双一次補間面へ morph**（外周バンドのみ）して
  隙間・段差を原理的に発生させない。パッチ位置は地形グリッドにスナップ（1 フレームの
  移動量は 0 or 1 セル、移動時は旧セルが画面上見えない端に置く）。
- **CPU 高度関数 `terrainHeight()` と GPU GLSL の完全一致**（value-noise のハッシュを
  uint 演算でミラー）。物理の接地判定・樹木/市街地/河川配置と見た目の高さがずれない。
- **起伏デザイン**: fBm 基底 + **リッジノイズの山脈**（2 系列 × 存在マスクで連なりを作る）+
  丘陵 + 微詳細。**河川ポリライン**（2 本）で谷を彫り、水面リボン（地形ベースから -14m、
  海面クランプ）を静的 geometry で沿わせる。全体平均を +63m リフトして内陸の「見かけの氾濫」を抑制。
- **ライティング**: 太陽 DirectionalLight に **影**（PCFSoft）を設定し、プレイヤー中心 ±shadowRange
  の ortho カメラで追従（`game.updateTerrainAndFog()`）。地形は cast+receive、建物/樹木/機体も
  影を出す。法線は頂点シェーダで中央差分（spacing の 0.6 倍ステップ）→ 斜面の明暗が明確。
  shadowRange/mapSize は品質プリセットで 1400〜2600m / 512〜2048 に制限（iPhone 負荷対策）。
- **大気遠近**: シーン Fog の near/far を**対地高度で展開**（最大 ×1.54/×2.21）+
  天候 fogScale。14〜23km の追加フェード（§3.5 の明滅対策を兼ねる）で遠景が階層的に淡くなる。
  海面の遠方は fog 色へ同期（`water.setHorizon`）し地平線で空と連続。海面の波・鏡面は
  6〜26km で減衰（FL350 で見えた鏡面エイリアスの白ドットが消失）。
- **地上の目印**: 農地パッチワーク（600m セルの手続きデカール、緩斜面〜中海抜のみ、
  20km 以遠は FS で打ち切り）、飛行場芝 tint、道路は**地形追従リボン**（旧: 平坦 Plane が
  起伏に埋まる/宙に浮く問題あり）、樹林帯・市街地は terrainHeight 準拠で配置。
- **距離感**: 近〜中の視界に 12.5m/50m 解像度の実際の起伏が入るため、パララックスと
  稜線の重なりで高度・速度感が立つ。遠景はリッジ山脈のシルエットが視差を持って流れる。

**品質プリセットへの追加**（`src/config/constants.ts`）:
`terrainNearSeg`(160/128/96)・`terrainMid`(high/medium で true)・`shadowRange`(2600/2000/1400m)。
low は中景パッチと影を切り、FS のノイズ系は距離ガードで全プリセット共通に軽量化。

**実測（Headless Chromium・SwiftShader）**: ドローコール 316 / トライアングル 260k
（地形 176k）/ shader program 25。flicker-test 4 ビュー全 PASS（coast [A] は 1.546→0.814 に改善:
遠景を粗メッシュ 1 枚で踏んだ方が深度競争が減る）。JS エラー 0 件。

**既知の制約**:
- 影の追従範囲は最大 ±2.6km。巡航高度からは機影が見えない（モバイル GPU で 4km 超の
  地形影は転写負荷と解像度のトレードオフが厳しく、近景の接地感・進入の影を優先）。
- パッチ境界の morph バンド内では近景メッシュが親面に寄るため、境界直近 500〜600m の
  微起伏が平滑化される（スナップ移動で境界が画面中央に留まらない設計）。
- iPhone 実機 FPS・発熱は未検証（この環境にハードが無い）。120k+51k+51k 頂点で頂点シェーダは
  fBm×約 10 の ALU 負荷 — 実機で重い場合は `QUALITY.low`（近景 96 分割・影 OFF）へ。

## 4. iPhone 向け最適化方針

| 対策 | 実装 |
|---|---|
| 横画面基本 | 縦画面オーバーレイで切替を案内（強制は保証しない — Safari 制約） |
| セーフエリア | `env(safe-area-inset-*)` を全 UI に適用 |
| ズーム/スクロール防止 | `touch-action:none` / `user-scalable=no` / `overscroll-behavior:none` |
| マルチタッチ | Pointer Events で指ごとにトラッキング |
| 解像度調整 | `devicePixelRatio` クランプ＋画質プリセット（高 2.0 / 中 1.5 / 低 1.0） |
| FPS 監視 | `core/quality.ts` に FPS サンプラー（Phase 6 で自動調整に接続） |
| 描画負荷 | 影カメラ限定・Instancing・フォグ・ポストプロセスなし |
| メモリ | ループ内オブジェクト再利用、シーン破棄時の dispose、動的生成なし |
| バックグラウンド復帰 | `visibilitychange` で自動一時停止＋時計リセット |
| WebGL 非対応 | エラーオーバーレイ表示 |
| 音声制限 | Phase 5。ユーザー操作（タップ）を起点に AudioContext 再開する設計 |

### 4.1 仮想スティック v3（固定ベース・低感度）
- ベース円をスティックゾーン中央下に**常時固定表示**（タッチ位置へジャンプしない）。
- 入力は**タッチ点からの相対ドラッグ**（v3.1: 一旦絶対マッピングにしたが、親指の初期接触が
  円心より左だと常に左バンク入力が掛かり「右へ倒すと左へ傾く」との指摘。相対方式で解消:
  触った瞬間＝中立、ドラッグ量＝舵）。ノブ描画は固定ベース円内にクランプ。
- 感度低減 3 段: デッドゾーン 8px / べき乗カーブ 1.45（中立付近が細かい）/
  スルトレート 2.2·s⁻¹（離陸直後の急な機首上げ防止）+ 満舵出力 0.9 上限。
- ベース直径は `clamp(96px, 36vh, 128px)`（低画面で計器盤に重ならない）。
- flight-note/sop-banner などの非操作レイヤー（pointer-events:none）同士の重なりは
  意図的として layout-audit で許容分類。
- **v3.2 ヨーク規約（2026-10-13）**: ピッチはボーイング ヨーク — **下ドラッグ=手前引き=機首上げ(+pitch)** /
  上=押し出し=機首下げ（物理 elevator +1=機首上げと一直線。キーボード ↑=機首上げは非反転のまま）。
  ロールは前どおり右=右。ノブ描画はロール成分で ±20° 回転（ヨーク傾き擬似）。

## 6. オートパイロット v4（2026-10-13 実装）

`src/sim/autopilot.ts`。入力 は `game.gameTelToApInput(telemetry)`（高度・気圧/対地速度・vs・姿态・
加速度ベクトル vx/vz・ILS ジオメトリ）、出力 は操舵命令（elevator 基準角 thDes / aileron・rudder / throttle）。
物理ループと同じ dt で `step()` を呼ぶ。**シミュレーション内側から見た「操舵装置」であり、
状態の直接上書きはしない**（AP が切れたら即ハンドフライト）。

### 6.1 ピッチ軸（法則 v4）

| モード | vsDes（目標昇降率） | 備考 |
|---|---|---|
| ALT | `clamp(Δalt×1.15, ±8)`、\|Δalt\|<40 でテーパー |  capture=engage 時現高度 |
| V/S | 選択 vs（±6,000 ft/min 範囲） | |
| APPR | `−GS勾配×ias + clamp(−gsDev×0.35, ±3.2)` |  \-12..6 m/s、gsDev で glide slope 捕捉 |

vsDes → スラスト目標（**仮想高度積分**による位置則。純レート則は姿勢ループと釣り合って
vs=1.4 m/s に停滞する構造的欠陥があった — 2026-10 トレースで実証）:

```
VS : vsAltV += vsDes·dt;  dV = clamp(vsAltV − (alt − vsAltRef), ±240)
     vsPosTerm = 0.05·dV + 0.45(vsDes − vs)
ALT: vsInt = clamp(vsInt + (vsDes−vs)·0.05·dt, ±5)·(1−0.8dt)
     vsPosTerm = vsInt + 0.45(vsDes − vs)
thDes = clamp(0.022·(dAlt + turnComp) + vsPosTerm, −4.5, +12)   // turnComp=(1/cosφbank−1)·alt·0.5
```

内ループ（姿态・角速度）は PID + 抗 windup: `raw = itP + 0.25(thDes−θ) − 0.18·q`、
`itP += 0.15·err·dt − 3·(raw−sat)`（clamp ±0.4）。ゲインは内ループ単体グリッドサーチで調整
（カスケード sweep は発散領域に入り打ち止め — 教訓として記録）。

### 6.2 横軸・速度

- LNAV/HDG: 目標バンク `clamp(offDeg, ±28°)`、offDeg = 交差角 − `xtk×0.05 + ẏ×0.55`、
  協調 bank→roll 命令 + 微小 rudder。旋回中 bank>6° では降下補正 thDes += turnComp。
- LOC: localizer 偏差で intercept→track（±28°→±12°）、test で横方向 0.8 m。
- A/T: 目標 IAS との実差 ±1 m/s デッドバンド、`throttle += clamp(errAdj×0.05, ±0.30)/s`（0.02..1）。
- 安全性: 地上（AGL<30）でピッチ/スラスト不干渉、GPWC（150 ft・降下中）で ALT を現高度+400 に
  引き上げ go-around、APPR カットオフで復行ロジック、接地（onGround && ias>35）検知で自動 disconnect。

### 6.3 デバッグ・検証

- `game.ap.debugOn = true` → `ap.debug = {thDes, pitchErr, itP, q, pitch}`（発散解析用。本番では false）
- `scripts/autopilot-test.mjs`: AircraftPhysics を直接駆動する 30 アサート（ALT 精度±40 m /
  V/S 目標追従 / 旋回中高度 ±120 / LOC ±20 / GS ±12 / 自動接地切断 / 地上不干渉 等）。
  ブラウザ側 UI は browser-smoke がカバー（engage→strip→パネル ALT+300→切断）。
- 実測値: レベルオフ vs=−0.08 m/s、LOC 交差 0.8 m、GS 偏差 −1.5 m、接地 IAS 116 kt（35 ft flare 込）。
